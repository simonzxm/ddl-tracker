# 产品规范

本文定义 DDL Tracker MVP 的用户可观察行为。协议字段和数据库实现分别见[同步协议](./sync-protocol.md)与[后端设计](./backend-design.md)；术语以根目录的 [CONTEXT.md](../CONTEXT.md) 为准。

## 产品目标

DDL Tracker 是学生实际使用的课程 todo 工具，不只是截止时间目录。它通过校内学生众包建立共享课程任务，同时允许每名学生在共享任务之上保存私人信息与处理状态。

系统必须始终区分两类事实：

- 共享事实：教学班、课程任务、任务提案、准确性判断和任务评论。
- 私人事实：个人待办、个人任务详情、个人任务状态、关注教学班和自己的投票状态。

共享信息永远不能伪装成学校官方信息；私人信息永远不能因发布、合并、同步或审核操作而被隐式公开。

## 角色与访问

### 学生

- 通过部署指定的 OIDC Provider 登录；账户身份由已验证的 `(issuer, subject)` 确定。
- 登录后可浏览全部当前或即将开始学期的课程与教学班。
- 可浏览并贡献任何活动教学班，不要求先关注。
- 只能修改自己的私人数据、准确性判断和评论。
- 不能创建或修改课程目录。

### 维护者

维护者首先是普通校内账户，额外拥有课程导入、处理举报、隐藏内容、合并重复任务、暂停账户和管理角色的权限。所有动作必须通过受保护后端接口执行并留下审计记录，不能绕过业务规则直接修改数据库。

### 未登录访问

未登录只允许访问健康检查和 OIDC start/callback/exchange。课程目录、任务、评论、公开用户资料和同步接口均要求登录。

## 学校与课程目录

MVP 是单学校部署。学校名称、OIDC Provider/client 配置和时区是部署级配置，不存在多租户或 `school_id`。

目录层级固定为：

```text
学期（Academic Term）
└── 课程（Course，以课程号区分）
    └── 教学班（Class Section，以学校教学班 ID 区分）
        └── 课程任务（Course Task）
```

学期有三种展示状态：即将开始、进行中、已归档。状态默认由 manifest 中的起止日期和 `Asia/Shanghai` 推导，维护者可以临时覆盖。

- 只有即将开始或进行中的学期允许关注和众包写入。
- 归档学期仍可查看，但任务、提案、投票和评论只读。
- 举报与维护者处置不受归档限制。
- 课程任务归属于教学班，不归属于课程；不同教学班共享同一安排时，MVP 仍分别维护。

## 账户与公开身份

首次 OIDC 登录成功后，服务端从已验证 claims 生成稳定且唯一的初始用户名，并原子创建完整账户、OIDC identity 与设备会话。用户之后可修改用户名、显示名、头像和简介。

- 用户名使用 `[a-z0-9_]`，长度 3–32，当前必须唯一。
- 用户名可以随时修改，不设冷却期；旧用户名立即重新可用。
- 显示名允许 Unicode，允许重复，默认等于用户名。
- 用户名和显示名公开；OIDC issuer/subject、可选 email claim 和设备会话私有。
- 提案和评论显示作者当前用户名与显示名。
- 投票者身份不公开，只同步聚合票数和当前用户自己的判断。

## 关注教学班

- 学生关注的是教学班，不是课程，也不表示学校确认的正式选课。
- 关注后，该班所有当前共享课程任务自动进入学生待办范围，新任务也自动加入。
- 未关注教学班可按需获取一次当前快照，但不会持续接收增量。
- 浏览或贡献不会隐式关注教学班。
- 取消关注后停止同步该班公开增量，客户端可清理公开缓存；该学生已有个人详情和个人任务状态继续保存在服务端，重新关注时恢复。

## 共享课程任务

课程任务只表达“这些提案讨论的是同一个教学班事项”。它自身没有权威标题、截止时间或说明。

创建课程任务必须在一个事务中同时完成：

1. 创建课程任务容器。
2. 创建初始任务提案。
3. 将创建者对初始提案的准确性判断设为赞成。
4. 写入相应同步事件。

任何一步失败都不能留下空任务。若所有提案均被维护者隐藏，课程任务必须停止作为活动任务展示。

每个课程任务只对应一个截止时刻。一个 project 的 checkpoint 和 final submission 是两个课程任务；MVP 不支持多截止时间或重复规则。

## 任务提案

任务提案是一整组不可变候选信息：

- 必填：标题、精确截止时间。
- 可选：纯文本补充说明、来源说明、HTTPS 来源链接。
- 不支持附件、截图、HTML、Markdown 或只有日期没有时间的截止信息。
- 公开截止时间始终按 `Asia/Shanghai` 输入与展示，底层保存绝对时刻。

提案发布后不能编辑、撤回或删除。信息错误时，作者应新增提案，并可把自己对旧提案的判断改为反对或撤回。

### 精确重复

服务端只阻止规范化后完全相同的提案，不做模糊匹配或语义合并。规范化包括 Unicode NFC、统一换行、去除首尾空白、时间转为同一 UTC 时刻、URL canonicalization 和稳定空值表示。

同一任务下的内容指纹必须唯一。重复提交返回 `duplicate_proposal` 和已有提案 ID，不创建记录，也不自动改变投票。`HW3` 与 `Homework 3` 仍是不同内容。

## 准确性判断与领先提案

每名学生对每条提案只有一个当前判断：赞成、反对或撤回。判断只表示整组信息是否准确，不表示喜好、完成状态或对作者的评价。

服务端保存投票明细并维护聚合计数，但只向客户端公开：

- 赞成票数。
- 反对票数。
- 当前用户自己的判断。

官方排名使用 95% Wilson score 下界，`z = 1.96`。无票提案分数为 `0`。分数相同时依次比较：总票数更多、创建时间更早、UUID 字典序更小。

对 `n = up + down > 0`、`p = up / n`：

```text
score = (p + z²/(2n) - z × sqrt((p(1-p) + z²/(4n))/n)) / (1 + z²/n)
```

实现应把极小的负浮点误差 clamp 为 `0`，并以仓库 JSON 测试向量为跨语言判断依据。

排名第一的可见提案称为领先提案，但不是官方事实。所有可见提案仍可查看。

置信状态：

- `pending_verification`：领先提案总票数少于 3。
- `disputed`：总票数至少 3，且反对占比至少三分之一，或者它与第二名 Wilson 分数差小于 `0.05`。
- `supported`：不满足以上条件。

只有一个可见提案时不执行第二名差距判断。被隐藏提案不参与排名。

仓库提供官方参考实现和 JSON 测试向量。官方客户端必须通过这些向量；第三方客户端被建议复用，但协议允许它们自行展示原始票数或采用其他排名，且不同结果不能宣称为官方排名。

## 个人待办与私人覆盖

### 个人待办

个人待办只有本人可见，可关联教学班，也可不关联课程范围。

- 标题必填。
- 截止时间可选；未设置时属于未安排待办。
- 可保存私人备注。
- 可编辑、删除，不保留用户可见修订历史。
- 所有时间统一按 `Asia/Shanghai` 处理。

### 个人任务详情

每名学生可以在一个共享课程任务下保存一份私人详情，包含可选的私人标题、私人截止时间和私人备注。个人详情优先用于该学生自己的列表展示，并明确标注“仅自己可见”；公开领先提案仍可查看。

个人任务详情可编辑、删除，不保留修订历史。仅完成或忽略任务不要求先创建个人详情。

### 个人任务状态

共享课程任务对每名学生可处于待处理、已完成或已忽略状态。状态只影响本人，可随时重新打开。

- 领先提案变化不会自动重置已完成状态。
- 客户端应提示共享任务信息发生变化，由学生决定是否重新设为待处理。
- 关注教学班后，任务默认处于待处理；已完成和已忽略任务可从活动列表弱化或隐藏。

### 合并个人待办

学生可以把个人待办合并到已有课程任务：

- 原标题、截止时间和备注转为个人任务详情。
- 原处理状态转为该课程任务的个人任务状态。
- 不公开任何私人字段。
- 合并后只保留一个待办入口。

### 发布私人信息

客户端必须显式提交即将公开的标题、截止时间、说明和提案依据；后端不能只接受“公开此私人记录”的隐式指令，也不能自动复制私人备注。

- 发布个人待办：必须选择教学班；若无对应课程任务，则创建课程任务和初始提案，再把私人记录关联过去。
- 发布个人任务详情：在现有课程任务下创建新提案。
- 发布不改变或删除私人内容。

## 任务评论

- 评论挂在整个课程任务下，不挂在单个提案下。
- MVP 是单层时间正序讨论，不支持回复树、评论投票或富文本。
- 作者可编辑评论；每次编辑产生不可变修订，当前内容指向最新修订。
- 所有登录学生可按需查看公开修订历史，默认只展示最新版并标注已编辑。
- 作者可软删除评论。普通学生只看到删除占位，不能查看正文或历史；作者和维护者可按权限查看保留记录。
- 教学班快照和增量只同步当前评论、修订号、已编辑标记和删除状态；完整历史通过独立分页读取接口获取。

## 举报、隐藏与重复任务合并

学生可举报课程任务、提案或评论。举报人、理由和维护者处理备注只对举报人本人及维护者可见；被举报者只看到最终公开处置。MVP 不实现申诉流程。

维护者可以隐藏和恢复共享内容：

- 隐藏不是删除，底层记录和审计保留。
- 隐藏提案退出排名。
- 隐藏课程任务停止展示公开内容，但个人详情与个人任务状态继续供本人使用，并标注共享内容已隐藏；恢复后自动重连。

维护者可以把两个同一教学班下的重复课程任务合并：

- 来源任务永久重定向到目标任务。
- 内容不同的提案、投票和评论归入目标任务，保留各自 ID 与历史。
- 两边规范化后完全相同的提案合为一个 canonical proposal：优先使用目标任务已有提案，否则使用创建时间更早的提案；其他 proposal ID 保留历史重定向，不重复展示。
- 同一学生在重复提案上的同方向判断只计一次；相反判断合并为撤回，并向该学生同步需要重新判断的结果，不能替学生选择赞成或反对。
- 个人详情和状态重新关联目标任务。
- 若同一学生在两边都有不同个人详情，目标详情保留，来源详情转回独立个人待办，并同步需要处理的结果；不能静默覆盖或拼接。
- 上述转出的个人待办同时保留来源任务状态。没有个人详情冲突时，两个任务状态按 `已完成 > 待处理 > 已忽略` 合并；只有来源有状态时直接迁移到目标。

客户端创建前应提示可能重复，但后端不使用模糊匹配自动合并任务。

## 账户生命周期

### 暂停

维护者可暂停和恢复账户。暂停立即撤销全部会话并阻止登录、写入和私人同步；公开贡献不会自动消失，内容处置单独执行。

### 删除

账户删除后：

- 删除校内身份、会话、关注关系、私人待办、个人详情和个人任务状态。
- 公开提案、评论和投票保留以维持讨论与聚合结果。
- 所有保留贡献的作者统一显示为不可关联的“已注销用户”。
- 原用户名立即可由其他账户使用。

## MVP 明确不做

- Web、PWA、Swift、Kotlin、React Native 或其他客户端实现。
- TypeScript 客户端内核和 IndexedDB/SQLite adapter。
- 多学校、租户隔离和学校级管理后台。
- 学生创建课程或申请课程。
- 服务端提案排名和面向页面的聚合展示接口。
- 提醒、推送、邮件提醒、日历订阅或 iCalendar。
- 任务类型枚举、重复任务、多截止时间。
- 全校任务全文搜索。
- 第二个身份 Provider、账户合并或多 Provider 绑定。
- 附件、图片、HTML、Markdown。
- 评论回复树、评论投票和举报申诉。
